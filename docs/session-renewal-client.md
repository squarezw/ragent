# In-place OIDC session renewal

The protocol token/local JWT lifetime remains unchanged. Once `/api/user/me` verifies a user, the client records only that user's numeric ID and `auth_session_expires_at` (seconds); no OIDC token is exposed to browser storage. Normal anonymous entry still automatically redirects through OIDC, and explicit local logout keeps its existing reauthentication behavior.

`lib/sessionRenewal.ts` starts a same-origin hidden iframe at `/api/auth/oidc/start?mode=silent&expectedUserId=...&requestId=...` before expiry (45 seconds) or after a protected background401. The server owns PKCE/state/nonce, account constraint and prompt=none. A popup opened directly by the recovery button uses mode=popup/prompt=login. One browser document shares a single in-flight renewal. Responses must match exact app origin, actual iframe/popup Window and random request ID; only a native same-origin `/me` read confirming the previous account and new valid expiry permits continuation. Frames/listeners/timers are removed after completion; silent wait is bounded at15seconds. A user-initiated popup has240seconds (within the sealed transaction lifetime) for human password/SMS entry; closing it or receiving a callback/error settles promptly, and account-profile verification has its own short timeout.

A valid renewal updates the registered expiry and existing user context. Protected axios requests wait for imminent renewal; after401 only GET/HEAD are retried once. Writes, chat POSTs, accepted streams and tool work are never automatically replayed. Native chat fetch checks session before starting; initial401 can renew for the next deliberate send but does not resend that question. Established SSE keeps running while another request renews credentials.

After unsuccessful renewal the client locks further automatic attempts until deliberate recovery, shows a translated in-place sign-in overlay and keeps already authenticated children mounted. Draft, transcript and partial stream stay in their original React component. Popup cancellation, blocked popup, service failure or different-account login cannot replace the current user/conversation or trigger a page reload. This does not grant access: subsequent protected operations remain blocked/fail until authentication is restored. A second resource401 after verified renewal is returned as an API error rather than logging the whole app out.

When another tab already renewed the shared cookie, failed/timeout frame recovery can accept `/me` only for the same user and strictly newer future expiry. An unchanged old cookie cannot masquerade as successful renewal. Explicit logout cancels in-flight renewal and advances the client generation; late messages/results are ignored. If logout fails, renewal is re-enabled and the existing session can recover. Server logout marker checks remain authoritative.

This is not transcript persistence or global logout. Browser crashes/manual reloads and true account switches retain their existing application behavior; no private conversation data was added to localStorage. Silent SSO depends on a live center session and correct same-site frame policy. If interaction is required or frame policy blocks it, the popup recovery path preserves this document while the user signs in.
