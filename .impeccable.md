## Design Context

### Users
Enterprise internal employees using the platform for knowledge base management and intelligent Q&A. Users range from technical staff building RAG workflows to non-technical business staff consuming knowledge. Primary context: daily work tasks requiring quick access to organizational knowledge, document management, and AI-assisted answers. Multi-tenant with 4-tier RBAC (Super Admin > Tenant Admin > Department Admin > User).

### Brand Personality
**Professional, Reliable, Efficient** — The interface should feel like a trusted enterprise tool that gets out of the way and helps users accomplish tasks quickly. No flashiness or unnecessary decoration. Every element should earn its place.

### Aesthetic Direction
- **Visual tone**: Minimal, clean, content-first — inspired by Notion and Linear
- **References**: Notion (generous whitespace, typography-driven hierarchy), Linear (polished interactions, systematic design tokens, dark mode excellence)
- **Anti-references**: Overly decorated dashboards, cluttered enterprise UIs with too many competing elements, generic "AI-purple-gradient" aesthetics
- **Theme**: Supports both light and dark mode with dynamic primary color customization (8 presets + custom HEX). Default is neutral with clean grays.
- **Typography**: System font stack (Arial/Helvetica/sans-serif). Hierarchy through weight and size, not decoration.

### Design Principles

1. **Content over chrome** — Minimize decorative elements. Let data, text, and actions breathe. Generous whitespace is a feature, not waste.

2. **Quiet confidence** — Use subtle, refined interactions rather than loud animations. Status changes, loading states, and transitions should feel smooth and intentional.

3. **Progressive disclosure** — Show only what's needed at each step. Complex features (workflow editor, knowledge base config) should reveal depth gradually, not overwhelm upfront.

4. **Systematic consistency** — Every spacing value, color, and component should come from the design token system. No one-off magic numbers. HSL-based CSS variables enable runtime theming without component changes.

5. **Accessible by default** — Meet WCAG AA standards. Sufficient color contrast, keyboard navigation, focus indicators, and screen reader support as baseline expectations.

### Technical Design System
- **Framework**: Tailwind CSS v3 + Radix UI primitives + shadcn/ui patterns
- **Colors**: HSL CSS variables with 11-level primary scale (50-950), semantic status colors (success/warning/destructive/info), 5 gray scale variants
- **Spacing**: Tailwind default scale, cards use p-6, buttons px-4 py-2, inputs h-10
- **Border radius**: 0.5rem base (--radius), with lg/md/sm variants
- **Icons**: Lucide React
- **Animations**: tailwindcss-animate plugin, accordion transitions (0.2s ease-out)
- **i18n**: next-intl with 27 namespaces, EN + zh-CN
